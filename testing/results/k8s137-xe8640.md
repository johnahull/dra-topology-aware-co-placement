# DRA Topology-Aware Co-Placement — Fedora 44 + K8s 1.37 (base cluster)

**Platform:** Fedora 44 (kernel 7.1.12-200.fc44) + Kubernetes 1.37.0 (pkgs.k8s.io packages)
**Hardware:** Dell XE8640 (l42-h06-000-xe8640, 10.6.62.51) — 2-socket Intel Ice Lake (128 CPUs, 2 NUMA nodes), 4x NVIDIA H100 SXM5 80GB (on nouveau), ConnectX-6 + E810 NICs, NVMe
**Container Runtime:** containerd 2.3.4 (Fedora package, NRI enabled by default), runc 1.5.1
**CNI:** Calico v3.29.3
**Date:** 2026-09-01

---

## Summary

Stood up a clean single-node Kubernetes 1.37 base cluster on the XE8640 using released packages (no source build). This is the substrate for later DRA driver work; the DRA drivers, KubeVirt, and the NVIDIA GPU driver are intentionally **out of scope** for this session.

Core DRA is GA in 1.37 (`resource.k8s.io/v1` served out of the box). Three DRA extension feature gates relevant to topology co-placement are enabled on the **kubelet** (node-local). Control-plane extension gates were left at defaults deliberately — kubeadm's top-level `featureGates` only validates gates in kubeadm's own allowlist, and pushing alpha gates into the apiserver/scheduler blind risks a static-pod crashloop. They will be added per-driver later once a driver documents needing them, verifying each control-plane pod restarts cleanly.

### What Works

- Single-node control plane healthy (apiserver, scheduler, controller-manager, etcd), node `Ready`, control-plane taint removed
- GA DRA API surface: `resource.k8s.io/v1` — DeviceClass, DeviceTaintRule, ResourceClaim, ResourceClaimTemplate, ResourceSlice
- Kubelet DRA extension gates active (no gate errors in journal): `DRAPartitionableDevices`, `DRAConsumableCapacity`, `DRADeviceCompatibilityGroups`
- Static CPU manager policy (`cpuManagerPolicy: static`, `systemReserved cpu: "4"`), systemd cgroup driver
- 64 GiB of 2M hugepages reserved at boot, balanced 16384 pages per NUMA node
- IOMMU already enabled (`intel_iommu=on iommu=pt`) — 14 DMAR instances, each H100 in its own IOMMU group (verified prior session)

### Out of Scope (deferred)

- CPU / GPU / NIC / memory DRA drivers
- KubeVirt
- NVIDIA GPU driver — H100s remain on **nouveau** (fine for the base cluster; blocks CUDA compute and needs replacing before GPU DRA/VFIO work)
- Control-plane DRA extension feature gates (add per-driver)

### Notes / Gotchas

- Fedora ships CNI plugins to `/usr/libexec/cni`, but containerd/Calico default to `/opt/cni/bin`. Handled by adding both to containerd v2's `bin_dirs` (v2 supports multiple dirs) and creating `/opt/cni/bin` for Calico to install into.
- containerd 2.3.4 ships with NRI **enabled by default** (`disable = false`) — no config edit needed for NRI, unlike the Fedora 43 / containerd-from-main path in the 1.36 session. (The DRA memory driver's NRI v0.11 `UpdatePodSandbox` need was not exercised here since that driver is out of scope; revisit if it lands on this box.)
- dnf5 on Fedora 44 does not accept `--disableexcludes`; the legacy `exclude=` + `--disableexcludes` repo-pinning idiom was dropped from the kubernetes.repo.
- `/tmp` is tmpfs — the kubeadm config placed in `/tmp` was wiped by the reboot. Kept the config at `~/kubeadm-config.yaml`.
- kubeadm `ClusterConfiguration.featureGates` rejects component DRA gates ("not a valid feature name") — they are not kubeadm's own gates. Use per-component `extraArgs` if control-plane gates are needed later.

## Setup

### 1. Host prep

Kernel cmdline (IOMMU already set from a prior session; added hugepages):
```bash
sudo grubby --update-kernel=ALL --args="default_hugepagesz=2M hugepagesz=2M hugepages=32768"
# resulting: intel_iommu=on iommu=pt default_hugepagesz=2M hugepagesz=2M hugepages=32768
```

Extended root LV 15G -> 100G (VG had 429G free):
```bash
sudo lvextend -L 100G /dev/fedora_l42-h06-000-xe8640/root && sudo xfs_growfs /
```

Disabled zram swap persistently:
```bash
sudo swapoff -a && sudo dnf remove -y zram-generator-defaults
```

Kernel modules + sysctls:
```bash
printf "overlay\nbr_netfilter\n" | sudo tee /etc/modules-load.d/k8s.conf
sudo modprobe overlay br_netfilter
printf "net.bridge.bridge-nf-call-iptables=1\nnet.bridge.bridge-nf-call-ip6tables=1\nnet.ipv4.ip_forward=1\n" \
  | sudo tee /etc/sysctl.d/k8s.conf
sudo sysctl --system
```

### 2. Container runtime (Fedora package)

```bash
sudo dnf install -y containerd runc containernetworking-plugins
sudo containerd config default | sudo tee /etc/containerd/config.toml
# edits: SystemdCgroup = true ; bin_dirs = ['/opt/cni/bin', '/usr/libexec/cni']
sudo mkdir -p /opt/cni/bin
sudo systemctl enable --now containerd
```

### 3. Kubernetes 1.37 (pkgs.k8s.io)

`/etc/yum.repos.d/kubernetes.repo`:
```
[kubernetes]
name=Kubernetes
baseurl=https://pkgs.k8s.io/core:/stable:/v1.37/rpm/
enabled=1
gpgcheck=1
gpgkey=https://pkgs.k8s.io/core:/stable:/v1.37/rpm/repodata/repomd.xml.key
```

```bash
sudo dnf install -y kubelet kubeadm kubectl cri-tools
sudo systemctl enable kubelet
```

Reboot here to activate hugepages, then init.

### 4. Cluster init

`~/kubeadm-config.yaml`:
```yaml
apiVersion: kubeadm.k8s.io/v1beta4
kind: InitConfiguration
nodeRegistration:
  criSocket: unix:///run/containerd/containerd.sock
---
apiVersion: kubeadm.k8s.io/v1beta4
kind: ClusterConfiguration
kubernetesVersion: v1.37.0
networking:
  podSubnet: 192.168.0.0/16
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cgroupDriver: systemd
cpuManagerPolicy: static
systemReserved:
  cpu: "4"
topologyManagerPolicy: none
featureGates:
  DRAPartitionableDevices: true
  DRAConsumableCapacity: true
  DRADeviceCompatibilityGroups: true
```

```bash
sudo kubeadm init --config ~/kubeadm-config.yaml
mkdir -p $HOME/.kube && sudo cp -f /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# Calico
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.3/manifests/tigera-operator.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.3/manifests/custom-resources.yaml

# single-node scheduling
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
```
